## ۲) قبل / بعد، با عدد

### ۲.۱ محدودیت نرخ (بحرانی‌ترین یافته)

کد قدیمی (`includes/handlers/contact.php` در `21e9759`):

```php
if (time() - $time < HA_RATE_LIMIT_WINDOW && $count >= HA_RATE_LIMIT_MAX) { /* رد */ }
$count++;
@file_put_contents($bucket, json_encode(['n' => $count, 't' => $time]), LOCK_EX);
```

`$time` هرگز به‌روز نمی‌شد؛ بنابراین پس از سپری‌شدنِ نخستین پنجره، شرطِ `time() - $time < WINDOW`
برای همیشه `false` می‌ماند و **هیچ پیامی دیگر مسدود نمی‌شد**. شبیه‌سازیِ دقیقِ همان کد با ساعتِ مجازی:

| زمان (ثانیه) | کد قدیمی | کد جدید |
|---|---|---|
| ۰ / ۲۰ / ۴۰ | OK / OK / OK | OK / OK / OK |
| ۷۰۰ / ۷۶۰ / ۸۲۰ | OK / OK / OK | OK / OK / OK |
| ۸۸۰ … ۱۲۴۰ (۷ تلاش) | **همه OK** | همه BLOCK (با `retry` دقیق) |
| ۱۳۰۰ / ۱۳۶۰ | OK | OK (پنجره‌ی سوم) |
| **جمع از ۱۵ تلاش** | **۱۵ پذیرفته** | **۸ پذیرفته (مطابق سیاست)** |

سایر ایرادهای همان کد که برطرف شد:

| ایراد قدیمی | پیامد | اصلاح |
|---|---|---|
| کلیدِ باکت شامل `date('YmdH')` | یک فایلِ **جدید در هر ساعت** برای هر IP، بدون پاک‌سازی → رشد بی‌حدِ inode روی هاست اشتراکی | کلیدِ ثابت `sha256(scope|ip)` + GC خودکار + سقف ۴۰۰ فایل |
| خواندنِ فایل، سپس نوشتن با `LOCK_EX` | شرطِ مسابقه: چند درخواستِ همزمان هر سه از حد عبور می‌کنند | `fopen('c+')` + `flock(LOCK_EX)` روی خودِ باکت برای خواندن-تغییر-نوشتنِ اتمیک |
| `@file_put_contents` بدون بررسی | اگر `storage` نوشتنی نبود، محدودیت **بی‌صدا حذف** می‌شد (fail-open) | fail-closed: اگر باکت باز نشود، درخواست رد می‌شود و پیامِ راهنما با ایمیلِ پشتیبانی نمایش داده می‌شود |
| نبودِ حداقل فاصله | رگبارِ چند فرم در یک ثانیه ممکن بود | `HA_RATE_LIMIT_MIN_INTERVAL = 20` با `retry` دقیق |

## ۹) مسیرهای آزمون‌شده

هر ۱۷ مسیر با رندرِ واقعی (PHP 8.3) و بررسیِ کدِ وضعیت، `<h1>`، `aria-current`، خطای PHP،
`canonical`، `og:url`، `og:image`، JSON-LD، منابعِ خارجی و `data-hay`:

```
home  courses  articles  videos  audios  books  research  exercises  tips
about  contact  search  course&slug  lesson&slug  category&slug  category  article&slug
books&slug  research&slug  و مسیرِ نامعتبر (۴۰۴ واقعی)
```

**فرم تماس (end-to-end با کوکی و نشستِ واقعی):**
| سناریو | نتیجه |
|---|---|
| GET فرم | ۲۰۰ + توکنِ CSRF + کوکی `HttpOnly`/`SameSite=Lax` |
| POST با ورودیِ نامعتبر | ۵ خطای فیلد (نام/ایمیل/موضوع/پیام/رضایت) + `aria-invalid` + `aria-describedby` + بازگردانیِ مقادیر |
| POST بدونِ توکن | رد، با پیامِ «نشست شما تمام شده است» |
| POST با توکنِ غلط | رد |
| POST با `Origin` بیگانه | رد (منطق در ۹ سناریوی واحد تأیید شد) |
| POST با honeypot | «موفقیتِ» فریبنده و بدونِ ذخیره |
| POST معتبر | پیامِ موفقیت + افزودنِ سطرِ CSV (با نقل‌قول‌گذاریِ درست) |
| ۴ ارسالِ متوالی | چهارمی با پیامِ سقفِ پنجره و زمانِ انتظارِ فارسی رد شد |

**Lint سینتکسی:** ۴۱ از ۴۱ فایلِ PHP با `token_get_all(..., TOKEN_PARSE)` سالم؛ `node --check` برای هر دو فایلِ JS سالم؛ CSS متوازن (۶۴۳/۶۴۳ آکولاد).

## ۱۰) آمادگی برای انتشار

### مسدودکننده (Critical) — هیچ
همه‌ی مواردِ بحرانیِ یافته شده (محدودیت نرخِ بی‌اثر، نبودِ CSP، دسترسیِ وب به پوشه‌های داخلی،
کنتراستِ زیرِ AA، `<h1>` تکراری، `og:image` نامعتبر، `robots.txt` با دامنه‌ی جعلی) اصلاح و آزمون شدند.

### مهم (High) — ۲ مورد، هر دو **پیکربندیِ استقرار** هستند نه کد
1. **`HA_SITE_URL` خالی است.** تا وقتی پر نشود، `canonical` و `og:url` از `HTTP_HOST` درخواست ساخته
   می‌شوند؛ روی InfinityFree که یک دامنه‌ی `*.infinityfreeapp.com` و چند دامنه‌ی متصل دارد، می‌تواند به
   محتوای تکراری بینجامد. **اقدام:** دامنه‌ی نهایی را در `config/config.php` بگذارید.
2. **HTTPS فعال نیست.** `HA_FORCE_HTTPS = false` و بلوکِ تغییرِ مسیر در `.htaccess` کامنت است؛ کوکی نشست
   بدونِ TLS `Secure` نمی‌گیرد. **اقدام:** پس از صدورِ گواهی رایگان، هر دو را فعال کنید.

### متوسط (Medium)
3. `ServerTokens` و `expose_php` فقط در سطحِ `httpd.conf`/`php.ini` قابل تنظیم‌اند؛ در هاست اشتراکی معمولاً
   در دسترس نیستند. لایه‌ی `header_remove` + `Header unset` اضافه شد، اما اگر هاست `mod_headers` را بسته
   باشد، تنها لایه‌ی PHP باقی می‌ماند.
4. تستِ بصری با مرورگرِ واقعی انجام نشد (این محیط مرورگر ندارد)؛ RTL و نقطه‌های شکستِ ۳۶۰–۱۴۴۰px
   بر پایه‌ی بازبینیِ CSS و ساختارِ DOM سنجیده شده‌اند، نه رندرِ پیکسلی.
5. `.htaccess` با `AllowOverride` غیرفعال بی‌اثر است؛ در آن حالت فقط لایه‌ی PHP از سرصفحه‌ها محافظت می‌کند
   و `robots.txt`/`sitemap.xml` پویا کار نمی‌کنند (فایل‌های ثابت سرو می‌شوند).

### جزئی (Low)
6. توکنِ CSRF در هر نشست تازه می‌شود نه در هر ارسال (چند تبِ باز می‌توانند همزمان معتبر بمانند) — آگاهانه،
   برای نزدنِ تجربه‌ی کاربری.
7. `storage/messages/messages.csv` روی دیسکِ هاست است؛ دسترسیِ وب بسته است ولی توصیه می‌شود دوره‌ای
   دانلود و خالی شود (در README آمده).
8. صفحه‌های فهرست (courses/books/…) JSON-LD از نوع `ItemList` ندارند.

### درصدِ آمادگی (مستندبه‌شواهد)
| جنبه | درصد | مبنای عدد |
|---|---|---|
| امنیتِ کد | **۹۵٪** | ۱۵ سرفصلِ جدولِ امنیت: ۱۵ سبز؛ کسر به‌خاطر `expose_php`/`ServerTokens` خارجِ کنترل ما |
| سئو | **۹۰٪** | ۱۳ سرفصل: ۱۳ سبز؛ کسر به‌خاطر `HA_SITE_URL` خالی (پیکربندی) و نبودِ `ItemList` |
